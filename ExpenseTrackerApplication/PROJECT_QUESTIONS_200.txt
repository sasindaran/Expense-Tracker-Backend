                    SECTION 1: OBJECT-ORIENTED PROGRAMMING (OOP)

PILLARS OF OOP IN THE PROJECT
────────────────────────────────────────────────────────────────────

Q1. What are the four pillars of OOP?
A: Encapsulation, Inheritance, Polymorphism, and Abstraction.

Q2. Where is Encapsulation used in this project?
A: In all entity classes (User, Expense, Category, Role) where fields are 
   private and accessed through getters/setters generated by Lombok.
   Example: private Long id, private String email in User.java

Q3. How does Lombok support Encapsulation?
A: @Getter and @Setter annotations automatically generate getter/setter methods,
   maintaining encapsulation while reducing boilerplate code.

Q4. Where is Inheritance used in this project?
A: - All repository interfaces extend JpaRepository<T, ID>
   - ExpenseRepository extends JpaRepository<Expense, Long>
   - UserRepository extends JpaRepository<User, Long>
   - RoleRepository extends JpaRepository<Role, Long>
   - CustomUserDetailsService implements UserDetailsService interface

Q5. What methods are inherited from JpaRepository?
A: save(), findById(), findAll(), delete(), deleteById(), count(), 
   existsById(), flush(), saveAndFlush(), and many more.

Q6. Where is Polymorphism used in this project?
A: - Method overriding: CustomUserDetailsService overrides loadUserByUsername()
   - Interface implementation: Repositories implement JpaRepository methods
   - Spring's dependency injection uses polymorphism for bean injection

Q7. What is Runtime Polymorphism in this project?
A: When CustomUserDetailsService.loadUserByUsername() is called, the actual
   implementation is determined at runtime based on the object type.

Q8. Where is Abstraction used in this project?
A: - Repository interfaces abstract database operations
   - Service layer abstracts business logic from controllers
   - JpaRepository abstracts complex database queries
   - UserDetailsService abstracts user authentication logic

Q9. How does the Repository pattern demonstrate Abstraction?
A: It hides the complexity of database operations behind simple method calls
   like findByUser(), save(), delete() without exposing SQL queries.

Q10. What is the difference between Abstract Class and Interface in this project?
A: Interfaces are used (JpaRepository, UserDetailsService) to define contracts.
    No abstract classes are used in the current implementation.

CLASSES AND OBJECTS
────────────────────────────────────────────────────────────────────

Q11. How many entity classes are in this project?
A: Four entity classes: User, Role, Category, and Expense.

Q12. What is the purpose of @Entity annotation?
A: Marks a class as a JPA entity, mapping it to a database table.

Q13. What is the purpose of @Table annotation?
A: Specifies the database table name for the entity.
    Example: @Table(name = "users") maps User entity to "users" table.

Q14. What is a POJO in this project?
A: Plain Old Java Objects - entity classes like User, Expense are POJOs with
   private fields and public getters/setters.

Q15. How are objects created in this project?
A: - By Spring (dependency injection for services, controllers)
   - By JPA/Hibernate (when fetching from database)
   - By client requests (JSON deserialized to objects)
   - Using Lombok's @NoArgsConstructor, @AllArgsConstructor

RELATIONSHIPS BETWEEN CLASSES
────────────────────────────────────────────────────────────────────

Q16. What is @ManyToOne relationship?
A: Multiple entities can be associated with one entity.
   Example: Many Expenses belong to One User.

Q17. Where is @ManyToOne used in this project?
A: - Expense → User (many expenses belong to one user)
   - Expense → Category (many expenses belong to one category)
   - User → Role (many users can have one role)

Q18. What is the difference between @OneToMany and @ManyToOne?
A: @OneToMany is the inverse of @ManyToOne. One User has Many Expenses.
   Currently, only @ManyToOne is used (from the "many" side).

Q19. What is @JoinColumn annotation?
A: Specifies the foreign key column name in the database.
   Example: @JoinColumn(name = "user_id") creates user_id column in expense table.

Q20. What does optional = false mean in @ManyToOne?
A: The relationship is mandatory; the field cannot be null.
   Example: @ManyToOne(optional = false) means every Expense must have a User.

DEPENDENCY INJECTION
────────────────────────────────────────────────────────────────────

Q26. What is Dependency Injection?
A: A design pattern where dependencies are provided (injected) rather than
   created by the class itself.

Q27. What type of Dependency Injection is used in this project?
A: Constructor Injection (recommended approach).
   Example: ExpenseController receives ExpenseService via constructor.

Q28. What is @Autowired annotation?
A: Marks a constructor, field, or method for automatic dependency injection.
   Not explicitly used because constructor injection is implicit in Spring.

Q29. How does Spring know which beans to inject?
A: Spring scans for @Component, @Service, @Repository, @Controller annotations
   and creates beans automatically.

Q30. What is the benefit of Constructor Injection?
A: - Immutable dependencies (final fields)
   - Easy to test with mocks
   - Clear dependencies
   - Prevents null pointer exceptions

ANNOTATIONS
────────────────────────────────────────────────────────────────────

Q31. What does @RestController do?
A: Combines @Controller and @ResponseBody. Returns data directly (JSON/XML)
   instead of view names.

Q32. What does @Service annotation do?
A: Marks a class as a service layer component. Spring creates a bean for it.

Q33. What does @Repository annotation do?
A: Marks an interface as a data access layer component. Enables exception
   translation and component scanning.

Q34. What is @RequestMapping?
A: Maps HTTP requests to handler methods. Can specify URL path and HTTP method.
   Example: @RequestMapping("/expenses")

Q35. What is the difference between @RequestMapping and @GetMapping?
A: @GetMapping is a shortcut for @RequestMapping(method = RequestMethod.GET).
   More concise and readable.

Q36. What does @PostMapping do?
A: Maps HTTP POST requests to a handler method.
   Used in: addExpense() method.

Q37. What does @DeleteMapping do?
A: Maps HTTP DELETE requests to a handler method.
   Used in: deleteExpense() method.

Q38. What is @PathVariable?
A: Extracts values from the URI path.
   Example: @DeleteMapping("/{id}") with @PathVariable Long id

Q39. What is @RequestBody?
A: Binds the HTTP request body to a method parameter (deserializes JSON to object).
   Example: addExpense(@RequestBody Expense expense)

Q40. What does @Configuration annotation do?
A: Indicates that a class declares one or more @Bean methods.
   Used in: SecurityConfig.java

Q41. What is @Bean annotation?
A: Indicates that a method produces a bean managed by Spring container.
   Example: @Bean public PasswordEncoder passwordEncoder()

Q42. What does @EnableWebSecurity do?
A: Enables Spring Security's web security support.
   Used in: SecurityConfig.java

JPA BASICS
────────────────────────────────────────────────────────────────────

Q43. What is JPA?
A: Java Persistence API - a specification for object-relational mapping (ORM).

Q44. What is Hibernate?
A: An implementation of JPA specification. Spring Data JPA uses Hibernate.

Q45. What is @Id annotation?
A: Marks a field as the primary key of the entity.

Q46. What is @GeneratedValue?
A: Specifies how the primary key should be generated.
   Example: @GeneratedValue(strategy = GenerationType.IDENTITY) uses auto-increment.

Q47. What does GenerationType.IDENTITY mean?
A: Database auto-increment feature generates the primary key value.

Q48. What is @Column annotation?
A: Specifies the mapped database column for a field.
   Example: @Column(nullable = false, unique = true)

Q49. What does nullable = false mean?
A: The database column cannot contain NULL values (NOT NULL constraint).

Q50. What does unique = true mean?
A: The database column must contain unique values (UNIQUE constraint).

REPOSITORY METHODS
────────────────────────────────────────────────────────────────────

Q51. What is JpaRepository?
A: A Spring Data interface providing CRUD operations and JPA-specific methods.

Q52. How does findByUser() method work?
A: Spring Data JPA automatically generates a query based on the method name:
   SELECT * FROM expense WHERE user_id = ?

Q53. What is the naming convention for query methods?
A: findBy + FieldName. Spring generates the query automatically.
   Example: findByEmail generates: SELECT * FROM users WHERE email = ?

Q54. What does Optional<Expense> return type mean?
A: A container that may or may not contain a non-null value.
   Prevents NullPointerException.

Q55. How does findByIdAndUser() work?
A: Generates query: SELECT * FROM expense WHERE id = ? AND user_id = ?
   Returns Optional<Expense>.

Q56. What inherited methods does ExpenseRepository have?
A: save(), findById(), findAll(), delete(), deleteById(), count(), 
   existsById(), flush(), saveAndFlush(), deleteAll(), etc.

Q57. What is the difference between save() and saveAndFlush()?
A: save() may not immediately persist to database (batching).
   saveAndFlush() immediately flushes changes to database.

Q58. What does delete() method do?
A: Removes the entity from the database.

Q59. Is SQL written manually in this project?
A: No, Spring Data JPA generates SQL automatically based on method names
   and entity mappings.

Q60. Can you write custom queries in Spring Data JPA?
A: Yes, using @Query annotation with JPQL or native SQL.
   Example: @Query("SELECT e FROM Expense e WHERE e.amount > :amount")

EXPENSE OPERATIONS
────────────────────────────────────────────────────────────────────

Q166. How is a new expense created?
A: 1. Client sends POST request with expense JSON
   2. Controller extracts authenticated user
   3. Sets user on expense object
   4. Calls ExpenseService.addExpense()
   5. Service saves to database via repository
   6. Returns saved expense with generated ID

Q167. How are user's expenses retrieved?
A: 1. Client sends GET request
   2. Controller extracts authenticated user
   3. Calls ExpenseService.getExpensesByUser(user)
   4. Service queries repository.findByUser(user)
   5. Returns list of expenses

Q168. How is an expense deleted?
A: 1. Client sends DELETE request with expense ID
   2. Controller extracts authenticated user
   3. Calls ExpenseService.deleteExpense(id, user)
   4. Service verifies expense belongs to user
   5. If valid, deletes expense
   6. If invalid, throws exception

Q169. What validation is performed on delete?
A: Checks if expense exists AND belongs to the authenticated user.
   Prevents users from deleting other users' expenses.

Q170. What happens if expense not found during delete?
A: RuntimeException is thrown with message "Expense not found or access denied"

USER ISOLATION
────────────────────────────────────────────────────────────────────

Q171. How is data isolation between users achieved?
A: - All queries filter by user
   - Service layer validates ownership
   - User context from authentication

Q172. Can a user see another user's expenses?
A: No, findByUser() only returns expenses for the authenticated user.

Q173. Can a user delete another user's expense?
A: No, findByIdAndUser() ensures the expense belongs to the user.

Q174. Where is the user context obtained?
A: From Authentication object injected into controller methods.
   authentication.getName() returns the email.

Q175. What is Authentication object?
A: Spring Security object containing authenticated user's details and authorities.

Q191. What is Lazy Loading in JPA?
A: Related entities are loaded only when accessed, not immediately.
   Default for @ManyToOne is EAGER, @OneToMany is LAZY.

Q192. What is Eager Loading in JPA?
A: Related entities are loaded immediately with the parent entity.

Q193. What is the N+1 query problem?
A: When fetching a list of entities causes N additional queries for relationships.
   Can be solved with JOIN FETCH in JPQL.

Q194. What is a Transaction in Spring?
A: A unit of work that either completes entirely or rolls back entirely.
   Ensures data consistency.

Q195. Are repository methods transactional?
A: Yes, Spring Data JPA repository methods are transactional by default.

Q196. What is @Transactional annotation?
A: Marks a method or class as transactional. Can be added to service methods.

Q197. What is the difference between save() and persist()?
A: save() is Spring Data JPA method (returns saved entity).
   persist() is JPA EntityManager method (void, attaches entity to context).

Q198. What is EntityManager?
A: JPA interface for interacting with persistence context.
   Not directly used in this project (abstracted by repositories).

Q199. What is JPQL?
A: Java Persistence Query Language - object-oriented query language for JPA.
   Example: SELECT e FROM Expense e WHERE e.amount > 100
